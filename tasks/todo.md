# Google Maps API 場所検索実装計画

## 概要
現在のChase Task Appは静的な場所リスト（LocationSearchScreen.tsx:24-40）を使用していますが、これをGoogle Maps APIの Places API と連携させて、リアルタイムの場所検索機能を実装することができます。

## 調査結果

### 現在の状況
- ✅ 既存の場所検索UI（LocationSearchScreen.tsx）が存在
- ✅ Expo React Native環境で構築
- ✅ 静的な場所リスト（東京の主要駅など）を使用中

### Google Maps API費用（2025年最新情報）

#### 基本料金体系
- **月額$200の無料クレジット**（2025年2月28日まで）
- **2025年3月以降**: 各APIで月10,000回の無料リクエスト
- **従量課金**: 1,000リクエストあたり$2-30（APIによる）

#### Places API具体的費用
- **Autocomplete (New)**: 最初の12リクエストは課金、その後はセッション課金
- **Place Details**: Places API Place Details Essentialsで課金
- **マップ表示**: React Native Maps SDK経由は**無料**

#### 注意事項
- **2025年3月1日以降**: Places API等が「レガシーサービス」に指定
- 新規更新停止の可能性あり

## コスト見積もり

### 小規模使用（月1,000ユーザー、1人平均10回検索）
- **月間リクエスト数**: 10,000回
- **コスト**: $0（無料枠内）

### 中規模使用（月10,000ユーザー、1人平均10回検索）
- **月間リクエスト数**: 100,000回
- **コスト**: 約$20-40/月

### 大規模使用（月100,000ユーザー、1人平均10回検索）
- **月間リクエスト数**: 1,000,000回
- **コスト**: 約$200-400/月

## 実装上の注意点

1. **APIキーセキュリティ**: 環境変数で管理、GitHub等には含めない
2. **レート制限**: APIリクエスト数制限対策
3. **エラーハンドリング**: ネットワークエラーやAPI障害時の対応
4. **フォールバック**: 既存の静的リストとの併用
5. **キャッシュ**: 同じ検索クエリの結果をローカルキャッシュ

## 代替案
- **OpenStreetMap Nominatim API**: 無料だが精度が劣る
- **MapBox Places API**: Google Mapsより安価な場合がある
- **Azure Maps Search API**: Microsoftの地図サービス

## 推奨アプローチ
1. まず小規模でGoogle Places APIを導入
2. 使用量を監視して費用対効果を評価
3. 必要に応じて代替案への移行を検討
